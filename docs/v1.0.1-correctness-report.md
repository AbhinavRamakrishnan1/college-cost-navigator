### Authoritative reconciliation

D1/D2/D6/D7 implement the existing versioned contract and data-integrity requirements, not new federal formulas. D4 uses the contract's federal poverty-region tables; frozen values are unchanged. D5 follows the separately verified statutory Special Rule limitation, with certification deliberately unsupported in v1.

D3 was explicitly approved after statutory verification. [20 U.S.C. §1070a(b)(1)(B)](https://uscode.house.gov/view.xhtml?edition=prelim&num=0&req=granuleid%3AUSC-prelim-title20-section1070a) treats negative SAI as zero for Calculated Pell. The [January 30, 2026 FSA maximum-award announcement](https://fsapartners.ed.gov/knowledge-center/library/dear-colleague-letters/2026-01-30/2026-27-federal-pell-grant-maximum-and-minimum-award-amounts) establishes the $7,395 maximum Scheduled Award. [2026–27 FSA Handbook Volume 7, Chapter 2](https://fsapartners.ed.gov/knowledge-center/fsa-handbook/2026-2027/vol7/ch2-calculating-pell-grants) supports the documented rounding and unrounded COA-cap order. [Chapter 1](https://fsapartners.ed.gov/knowledge-center/fsa-handbook/2026-2027/vol7/ch1-student-eligibility-pell-grants) addresses Special Rule eligibility.

D8–D11 were reconciled before implementation in [the dated policy decision table](v1.0.1-policy-decisions.md), using the [May 1, 2026 RISE final rule](https://www.federalregister.gov/documents/2026/05/01/2026-08556/reimagining-and-improving-student-education-federal-student-loan-program-final-regulations), particularly §§685.208(b)(8)/(c), 685.209(b)(6)/(c)(5)(iii)/(d), and 685.210(a)(3). The explicit assessment baseline is September 19, 2026, not an implied perpetually current policy determination.

## Storage and compatibility

- Dexie database version **4 → 5** (native IndexedDB version **40 → 50**); household schema **2 → 3**; backup format **4 → 5**.
- Explicit transactional migration retains the entire original profile in `legacyProfile`, preserves meaningful nondefault values and both returns, canonicalizes residence, and marks ambiguous defaults unknown. Archived values remain local and available for review rather than being silently reused as confirmed facts.
- Existing schools, loans and projection assumptions remain in their original stores. New repayment history fields are optional in saved legacy records; missing required eligibility evidence fails closed.
- Invalid legacy schemas/residence fail migration rather than selecting guessed facts. The transaction protects original stored data.
- Version-4 backups are migrated through the same profile logic. Version-5 export/restore retains unknown states and archived inputs. Restore validates before transactional replacement; delete-all removes archived profile inputs too.
- Migration and backup tests verify preserved records, two returns, normalization and incomplete-state round trips. Browser coverage exercises an actual prior-version IndexedDB and the production download/delete/import journey.
