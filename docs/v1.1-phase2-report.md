# v1.1 Phase 2 — Guided setup, family workflows, and planning tools

Status date: September 20, 2026

## Scope completed

- Added an optional eight-step guided dependent-student household setup alongside the existing full form. Both paths write the same version-3 canonical household profile and use the same Formula A calculation adapter.
- Added first-use choices for a new household, the fictional Rivera demo, and borrowers who want to go directly to repayment.
- Added support-based FAFSA contributor guidance for parents who live together or apart, including separated, divorced, never-married, and remarried-parent cases.
- Added a local aid what-if workspace that compares selected hypothetical AGI and cash changes with the current profile without mutating the saved baseline. Applying a scenario requires a separate explicit action.
- Added a privacy-conscious browser-print summary for federal aid, saved schools, and an optionally selected repayment scenario.
- Added recurring and one-time extra-payment controls for Tiered Standard projections, including payoff timing, total paid, interest, ending balance, and comparison with the no-extra baseline.
- Improved narrow-viewport behavior and touch targets for the wizard review controls and mobile navigation.

No federal aid formula, repayment formula, policy JSON, Scorecard record, IndexedDB schema, or profile schema changed.

## Contributor workflow

The guide uses the current support-based FAFSA rule represented by the existing 2026–27 FSA Handbook source. Parents who are married and living together, and unmarried legal parents living together, are both included. When parents do not live together, the guide selects the parent providing greater financial support in the prior 12 months. A support tie or neither-parent case requires the parent with greater income and assets. A selected parent’s current spouse is included when that parent remarried.

Missing support, tie-breaker, relationship, or remarriage facts produce a clarification-required state. The guide never substitutes custody and never persists a competing contributor model. Its result populates the existing canonical `parentSingleParent` fact used by the calculator.

## Wizard architecture and fail-closed behavior

The guided flow covers student status, contributor household, parent income, filing and eligibility facts, parent assets, student income, student assets, and review. Values remain in component state until the user saves locally. Back and next preserve entries. Unknown remains `null`; a confirmed zero remains `0`. Progress may be saved with unknown answers, but calculation remains blocked until the canonical profile adapter reports a complete supported Formula A profile. Independent students remain explicitly unsupported.

The review summarizes completion without echoing raw income, tax, or asset values. The fictional Rivera profile may enter the same review and save path, and still produces SAI 2,069 and a $5,325 Pell Scheduled Award estimate.

## What-if behavior

What-if scenarios are structured clones of the stored profile and remain browser-local and ephemeral. The comparison shows current versus scenario SAI, Pell Scheduled Award estimate, and Pell path. Unknown or unsupported hypothetical facts fail closed without a numeric guess. Exiting discards the scenario; the saved profile changes only after the user selects **Apply and save scenario**.

## Repayment extra-payment scope

The extra-payment controls generate the schedule already supported by the existing projection engine. V1.1 Phase 2 exposes that schedule only for Tiered Standard, where recurring and one-time timing semantics are unambiguous. The UI compares projected payoff timing, total paid, and interest against the no-extra baseline. RAP and IBR continue to use explicit no-extra projections; no income-driven-plan formula or assumption was extended.

## Print-summary privacy

The print route uses the browser’s print dialog and assembles the summary from local IndexedDB plus the same-origin static Scorecard snapshot. It includes the policy year, generated date, federal SAI/Pell result, selected school averages, an optional repayment scenario, methodology context, and limitations. It intentionally excludes raw income, tax-return facts, asset balances, internal identifiers, and hidden calculation flags. Nothing is uploaded to generate or print the summary.

## Deferred and warnings

- Independent-student Formula B/C remains unsupported.
- Extra-payment schedules are not exposed for RAP or IBR.
- What-if controls intentionally cover a small set of high-value aid inputs; they are not a tax planner or institutional-aid model.
- Print output depends on the user’s browser print settings and is not a server-generated archival document.
- Automated axe checks and viewport assertions do not replace manual testing with multiple screen readers, assistive technologies, printers, and mobile browsers.
- The test runner exhausted its default parallel worker heap in this environment. Final Vitest and Playwright gates passed serially with an explicit Node heap allowance for Vitest; no application defect was inferred from the runner limit.
- No v1.1 Phase 3 work was started.
