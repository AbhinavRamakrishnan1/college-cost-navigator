# v1.1 Phase 3 funding planner UI and comparison

Status date: September 23, 2026  
Scope: ephemeral four-/five-year planner, exactly two-school comparison, and browser-print summary

## Architecture and privacy

The `/app/funding-planner` route is reachable from school details, saved-school comparison, and navigator navigation. Its ten-step workflow covers school/scope, costs, non-loan aid, family cash, student borrowing, Parent PLUS, disbursement/rate assumptions, annual results, graduation debt, and comparison/print.

React gathers and presents facts while `src/lib/funding/plannerAdapter.ts` performs pure orchestration. The adapter accepts typed explicit inputs, safely validates them, calls the verified cost, non-loan funding, origination, allocation, ledger, and interest engines, and returns complete/incomplete/unsupported/error results with independently usable partial metrics. It does not mutate the household profile or Scorecard records.

The plan exists only in React memory. Entry-point route state is consumed and removed so reload clears the plan. No planner values are written to IndexedDB, localStorage, sessionStorage, query parameters, analytics, logs, or remote services. Existing saved schools and household profiles are read locally but never mutated. Database schema remains 5, profile schema remains 3, and no migration was added.

## Explicit scope and origination facts

The planner does not fabricate dependency status, education level, enrollment structure, institution/program identifiers, grade level, academic-year dates, higher-limit status, or institutional-limit status. A supported dependent profile plus explicit undergraduate, full-time standard-year, actual UNITID, program, grade, academic-year, enrollment-period, and restriction facts are required.

Missing profiles remain incomplete. Independent, graduate/professional, part-time, nonstandard, transfer-specific, and shortened/nonterm cases fail closed. Grade level is not inferred from planner-year number.

Structured history captures:

- Direct and Subsidized aggregate-countable outstanding principal
- categorized lifetime borrowing and consolidation attribution
- per-year Direct and Subsidized usage
- Parent PLUS per-year and cumulative usage

Missing history remains incomplete rather than zero. Higher-limit qualification supports qualified denial, qualified FAA circumstances, not qualified, unresolved, and stale states. A Parent PLUS denial alone never creates higher-limit eligibility.

Transition evidence supports unresolved, verified not applicable, verified applicable, and stale/expired states. Evidence remains bound to the actual selected UNITID, explicit program, and enrollment period. Every canonical statutory predicate must be resolved explicitly for a verified determination; the adapter never synthesizes enrollment, prior-disbursement, recipient, cancellation, continuity, leave, return, withdrawal, or expected-time facts. Parent identity remains separate from FAFSA contributor identity.

Institutional restriction status begins unknown and blocks allocation. A known shared institutional total remains blocked until the user explicitly confirms allocations among Direct Subsidized, Direct Unsubsidized, and Parent PLUS. No priority is invented.

## Unknown defaults and provenance

College Scorecard published cost and tuition may seed a school-specific starting point with Scorecard year and UNITID provenance. The UI labels those values as published starting points, not personalized bills or average net prices. Housing, books, transportation, and other component costs begin unknown.

The current verified Pell Scheduled Award may seed Year 1 with verified local-calculation provenance. Future Pell, institutional grants, outside scholarships, other grants, and family cash begin unknown. Each non-loan fact supports known, assumed, and unknown states; deliberate known or assumed $0 remains distinct from unknown. Assumptions require explanations. Renewal, institutional aid, and family cash are never inferred from SAI.

Annual overrides use an explicit enabled state, so a legitimate $0 override is distinct from no override. Switching from a five-year custom schedule to a four-year horizon produces a recoverable validation error rather than a render crash.

## Dates, interest, and graduation debt

First-disbursement and graduation/planning-end dates begin blank. Each year requires an explicit first-disbursement date plus acceptance of the labeled one-disbursement planning template. Qualifying subsidy-enrollment treatment and the engine's no-voluntary-in-school-payments limitation also require explicit confirmation.

Known federal cohorts retain canonical dated rates. Unknown future rates remain unknown unless the user supplies an explicit shared assumption. Unknown future fee windows remain incomplete; the last verified fee is never reused.

The graduation view is headed `PROJECTED NEW DEBT FROM THIS PLAN AT GRADUATION`. Student debt remains separate from each parent's Parent PLUS debt. Partial debt is labeled partial/incomplete, and elected principal omitted by an incomplete allocation is disclosed.

## Roll-forward and partial-result semantics

History rolls forward only from successful ledger allocations. Incomplete, unsupported, assumption-required, institution-allocation-required, and exceeds-limit elections do not consume later-year headroom.

Program cost is aggregated independently from funding completeness. Four known cost years therefore remain fully visible when future Pell is unknown. Funding aggregation is category-level: known Pell is retained in a partial grants subtotal even when an institutional grant or scholarship remains unknown. Every summary metric has independent complete/partial/incomplete metadata, a resolved-year count, and specific reasons. A known subset is labeled `Known partial total`; unavailable values never render as $0, and a partial metric without a meaningful subtotal is shown as incomplete rather than as a contradictory partial-unavailable value.

Remaining gap and projected excess funding/surplus are separate values. A gap is clamped at zero only for the gap metric; loan proceeds in excess of cost appear as surplus annually, in aggregates, comparison, and print.

Graduation debt exposes student subsidized and unsubsidized principal, total student principal, known accrued interest, and informational principal-plus-interest separately from Parent PLUS principal, interest, and informational total. Available per-parent details remain separate. The display and print explicitly state that capitalization is not applied in the graduation snapshot.

Allocation failures display the verified engine's requested, allowed, applied, and binding-reason values. A known shared institutional cap without an explicit cross-loan split now carries its known requested total and total cap in that structured failure result while applying $0. Gross principal, fees, and net proceeds remain distinct.

## Comparison and print

One saved school may be planned alone, or exactly two selected saved schools may be compared. A third selection is rejected with an explicit explanation. Per-school costs, aid, programs, elections, and evidence remain independent; horizon, growth, graduation date, and future-rate assumptions are intentionally shared.

The comparison produces no winner, rank, traffic light, affordability/ROI score, recommendation, or attendance verdict. Browser print includes Scorecard data year, snapshot version, UNITID, material accepted assumptions (horizon, growth, overrides, one-disbursement template and dates, subsidy and no-payment treatment, rate assumptions, program/enrollment scope, grades, graduation date, transition and institutional states), year-by-year cost/funding/gross/fee/net/gap/surplus values, independently labeled totals, graduation-debt estimates, and specific missing reasons. Detailed household income, tax, and asset values are excluded.

The final v1.1 product pass adds adapter-derived plan completeness, a Decision Season Checklist, a visual funding timeline, selective provenance badges, calculation disclosures, and one React-memory-only baseline-versus-what-if scenario. These are presentation and workflow features: both baseline and alternate calculations use this same adapter, no planner state is persisted, and no federal calculation or policy dataset changed. The repayment call-to-action transfers no balance or financial value and requires separate confirmation in the existing repayment planner.

## Validation, accessibility, and mobile behavior

Editable values are safe-parsed before domain engines run. Invalid growth, rate, date, amount, schedule, explanation, and borrowing-history value return typed validation errors rather than throwing during render. Inline errors use `aria-invalid` and `aria-describedby`. Each error-summary control carries its target step, year, and field ID; activating it changes the mounted step/year and focuses the actual control rather than leaving a dead hash link.

The workflow uses semantic headings, fieldsets/legends, labeled inputs, keyboard-operable step/year controls, visible textual states, reduced-motion-compatible styles, and a stacked narrow-screen comparison. Automated axe checks cover desktop and mobile. Active-step contrast was strengthened after an automated regression identified insufficient contrast.
